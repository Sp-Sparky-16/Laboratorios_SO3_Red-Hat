#!/bin/bash

	* * * * * /bin/bash /ruta/absoluta/sync_script.sh >/dev/null 2>&1

======
EXTRAS
======
Práctica 1: Sincronización de carpetas con Rsync

Creación de archivos en lote

mkdir -p ~/sync_folder && cd ~/sync_folder

Explicación: Crea el directorio de trabajo (el parámetro -p evita errores si la carpeta ya existe) y entra en él inmediatamente.

touch archivo_{1..100}.txt

Explicación: Crea 100 archivos vacíos en un solo paso mediante expansión de corchetes.

Parámetros alternativos: touch {a..z}.txt (para generar archivos por letras).

Sincronización manual remota

rsync -avz -e ssh ~/sync_folder/ usuario@IP_SERVIDOR_REMOTO:/ruta/destino/

Explicación: Sincroniza el contenido local con el servidor destino.

Parámetros utilizados:

-a (archive): Conserva permisos, propietarios, fechas de modificación y enlaces simbólicos.

-v (verbose): Muestra el detalle de la transferencia en consola.

-z (compress): Comprime los datos durante el transporte para ahorrar ancho de banda.

-e ssh: Especifica que la transferencia se hará a través del protocolo seguro SSH.

Parámetros recomendados:

--delete: Borra en el destino los archivos que hayan sido eliminados en el origen.

-P (o --progress): Muestra barras de progreso y permite reanudar descargas interrumpidas.

Automatización con Crontab

crontab -e

Explicación: Abre el editor del programador de tareas del usuario actual.

* * * * * /bin/bash /ruta/absoluta/sync_script.sh >/dev/null 2>&1

Explicación: Define una tarea que ejecuta el script de sincronización cada minuto. Los 5 asteriscos representan: minuto (*), hora (*), día del mes (*), mes (*), día de la semana (*). La redirección >/dev/null 2>&1 descarta las salidas estándar y de error para evitar acumular correos o logs del sistema.

Práctica 2: Cluster de Alta Disponibilidad con Pacemaker y Corosync

Configuración del Entorno y Red

hostnamectl set-hostname nodo1

Explicación: Define el nombre de red persistente de la máquina actual.

subscription-manager repos --enable=rhel-10-for-x86_64-highavailability-rpms

Explicación: Habilita el repositorio oficial de Red Hat que contiene los paquetes de Alta Disponibilidad.

dnf groupinstall -y "High Availability"

Explicación: Instala todos los componentes y dependencias del grupo de Alta Disponibilidad de RHEL.

Administración del Cluster con PCS

systemctl enable --now pcsd

Explicación: Habilita e inicia el demonio de control de la interfaz/CLI del cluster.

pcs host auth nodo1 nodo2 -u hacluster

Explicación: Autentica los nodos del cluster contra el demonio pcsd usando el usuario del sistema hacluster.

Nota de sintaxis: En versiones modernas de RHEL se usa pcs host auth en lugar del antiguo pcs cluster auth.

pcs cluster setup ha_cluster nodo1 nodo2 --force

Explicación: Genera los archivos de configuración del cluster (corosync.conf) e integra los nodos definidos bajo el nombre ha_cluster.

pcs cluster start --all / pcs cluster enable --all

Explicación: Inicia los servicios del cluster (Corosync y Pacemaker) en todos los nodos y configura su arranque automático con el sistema.

pcs property set stonith-enabled=false

Explicación: Desactiva el mecanismo de esgrima (fencing/STONITH). Es obligatorio en entornos de laboratorio sin dispositivos de apagado por hardware.

pcs property set no-quorum-policy=ignore

Explicación: Le indica al cluster de 2 nodos que ignore la pérdida de quorum y mantenga los recursos activos aunque falle un miembro.

pcs resource create Virtual_IP ocf:heartbeat:IPaddr2 ip=10.0.0.200 cidr_netmask=24 nic=enp0s3 op monitor interval=10s

Explicación: Crea el recurso de la IP flotante administrada por Pacemaker.

Parámetros:

ocf:heartbeat:IPaddr2: Agente OCF encargado del manejo de direcciones IP asociadas a interfaces físicas.

ip: La dirección IP Virtual elegida.

cidr_netmask: Máscara de red en notación CIDR.

nic: Nombre específico de la tarjeta de red física donde se montará el alias IP.

op monitor interval=10s: Comprueba el estado de la IP cada 10 segundos.

pcs status

Explicación: Muestra el estado operativo del cluster, los nodos en línea y en qué nodo está ejecutándose cada recurso.

Práctica 3: Cluster de Alta Disponibilidad HTTP con Keepalived

Gestión del Servidor Web (Nginx/Apache)

dnf install -y nginx / dnf install -y httpd

Explicación: Instala el servidor web elegido desde el gestor de paquetes.

ss -tulpn | grep :80

Explicación: Muestra qué proceso o demonio (httpd, nginx, etc.) tiene bloqueado el puerto HTTP 80.

Parámetros: -t (TCP), -u (UDP), -l (Listening/Escuchando), -p (Muestra PID/Proceso), -n (Formatos numéricos de puertos).

Servicio Keepalived

dnf install -y keepalived psmisc

Explicación: Instala Keepalived junto con el paquete psmisc (que provee la herramienta killall requerida para verificar el estado de los procesos).

setenforce 0

Explicación: Pone SELinux en modo permisivo temporalmente para evitar que bloquee la ejecución de los scripts internos de comprobación de Keepalived.

firewall-cmd --permanent --add-protocol=vrrp && firewall-cmd --reload

Explicación: Permite la comunicación del protocolo VRRP (ip protocol 112) a través del firewall de Red Hat para que los nodos transmitan sus latidos (heartbeats) correctamente.

keepalived -t -f /etc/keepalived/keepalived.conf

Explicación: Verifica la sintaxis del archivo de configuración sin levantar el servicio.

Parámetros: -t (test de sintaxis), -f (Ruta específica del archivo de configuración).

Estructura del archivo /etc/keepalived/keepalived.conf

vrrp_script check_nginx { script "/usr/bin/killall -0 nginx" ... }

Explicación: Bloque que ejecuta la prueba de salud del servicio web cada determinado intervalo de tiempo.

vrrp_instance VI_1 { ... }

Explicación: Define la instancia del enrutador virtual. Sus parámetros principales son:

state MASTER / state BACKUP: Define el rol predeterminado del nodo.

interface enp0s3: La tarjeta de red física sobre la que se asignará la IP flotante.

virtual_router_id 51: Identificador del grupo VRRP (debe ser idéntico en ambos servidores).

priority 101 (Master) / priority 100 (Backup): Prioridad del equipo. El valor más alto obtiene la IP flotante.

virtual_ipaddress { ... }: La dirección IP Virtual asignada al grupo.
